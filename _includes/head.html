{%- seo -%} {%- comment -%} Asset cache versioning (#61, follow-up to #58) - see AGENTS.md "Asset cache versioning". GitHub Pages serves `/assets/**` with `cache-control: max-age=14400` from a fixed URL, so a returning visitor can render fresh HTML against a 4-hour-old asset. That is exactly how the #58 list sidebar went missing: the old stylesheet has no `.site-layout` grid, so the sidebar painted below the whole post list. `site.time` (epoch seconds) is the version token: it needs no plugin, honours a `time:` key in the config, and works with GitHub Pages `--safe`, with `bundle exec jekyll serve` and with the E2E build. Trade-off: it follows the *build*, not the bytes, so an asset is re-fetched once per deploy (~18KB for the stylesheet) even when it did not change - a superset of "the content changed", which can never serve a stale layout. A real content hash needs a Jekyll plugin, which GitHub Pages does not run. Any new fixed-URL asset served under /assets/ must be versioned the same way. {%- endcomment -%} {%- assign asset_version = site.time | date: '%s' -%} {%- feed_meta -%} {%- if jekyll.environment == 'production' and site.google_analytics -%} {%- include google-analytics.html -%} {%- endif -%} {%- include custom-head.html -%}
